# ТЕХНИЧЕСКОЕ ЗАДАНИЕ НА СОЗДАНИЕ АВТОМАТИЗИРОВАННОЙ СИСТЕМЫ
### Соответствует требованиям ГОСТ 34.602-89 и ISO/IEC/IEEE 29148:2018
**Наименование системы:** Высоконагруженная SMM-платформа (Enriched Specification)
**Шифр документа:** АС-SMM-2026-NPU
**Дата утверждения:** 2026 г.

---

## 1. ОБЩИЕ СВЕДЕНИЯ
1.1. Полное наименование системы: Автоматизированная система «Высоконагруженная SMM-платформа (Enriched Specification)».
1.2. Шифр темы: АС-SMM-2026-NPU.
1.3. Разработчик: Dual-Agent Cognitive Engine (Gemini 3.1 Pro + Intel AI Boost NPU).
1.4. Заказчик: Предприятие-Оператор сервиса.
1.5. Плановые сроки создания: I–II квартал 2026 года.
1.6. Порядок финансирования: В соответствии с финансовой сметой Unit_Economics_Budget.json.

## 2. НАЗНАЧЕНИЕ И ЦЕЛИ СОЗДАНИЯ (РАЗВИТИЯ) СИСТЕМЫ
2.1. Назначение системы: Автоматизация процессов приема, маршрутизации и контроля исполнения заказов в социальных сетях с использованием искусственного интеллекта на физическом нейропроцессоре NPU.

2.2. Цели создания системы и критерии эффективности:
  - Сокращение времени оформления заказа розничным пользователем с 3 минут до 15 секунд;
  - Автоматическая маршрутизация заказов на 5 внешних API провайдеров с балансировкой нагрузки;
  - Достижение юнит-экономики: отношение LTV/CAC >= 3.0, себестоимость серверной обработки 1 транзакции <= $0.0005;
  - Обеспечение непрерывной работы при нулевом бюджете на простои (Uptime >= 99.95%).

## 3. ХАРАКТЕРИСТИКА ОБЪЕКТОВ АВТОМАТИЗАЦИИ
3.1. Условия эксплуатации: Серверный распределенный кластер и локальные рабочие станции с поддержкой Intel NPU.

3.2. Матрица ролей и объектов автоматизации:
  - Роль [Guest]: Быстрый заказ по ссылке за 1 клик без регистрации;
  - Роль [Wholesale_Client]: Оптовые заказы через API и личный баланс;
  - Роль [Administrator]: Управление провайдерами, наценкой и маржой;
  - Роль [Support_Agent]: Обработка тикетов с привязкой к номеру заказа;

## 4. ТРЕБОВАНИЯ К СИСТЕМЕ
4.1. Требования к системе в целом:
  - Надежность: Среднее время наработки на отказ (MTBF) >= 2000 часов;
  - Безопасность: Соответствие требованиям ГОСТ Р 56939-2024 и ФСТЭК (модель угроз STRIDE, Zero Trust, Rate Limiting 100 req/min);
  - Эргономика: Адаптивный веб-интерфейс, поддержка темной/светлой темы, мгновенная валидация ссылок за 1.0 мс на NPU;
  - Условия эксплуатации: Аппаратный профиль ноутбука/сервера — Intel Core Ultra 5 125H, 16 ГБ RAM (модель NPU занимает не более 550 МБ RAM в INT8).

4.2. Требования к функциям (подсистемам):
  - Подсистема Быстрого заказа (Guest Funnel): автоматическое распознавание социальной сети по введенному URL, отображение 3 целевых тарифов, оплата через СБП и банковские карты;
  - Подсистема Личного кабинета (Client Portal): 4 типовых модуля по отраслевому эталону (Заказ, История, Баланс, API реселлеров);
  - Подсистема Администратора (Admin Desk): 6 специализированных вкладок (Заказы, Провайдеры, Тарифы, Пользователи RBAC, Тикет-система, Финансовая сверка);
  - Подсистема Поддержки: Классическая тикетная очередь с фиксацией ID заказа и SLA первого ответа <= 4 часов.

4.3. Требования к видам обеспечения:
  - Математическое и алгоритмическое: Неавторегрессионные примитивы выбора (Laya-421M / Jev / ModernBERT) и генетический отбор L-MOPA;
  - Информационное: Реляционная СУБД PostgreSQL (партиционирование заказов по месяцам), кэш Redis Streams;
  - Программное: Python 3.11+, OpenVINO 2026.0, FastAPI / OpenAPI 3.1, Vitest;
  - Лингвистическое: Интерфейс пользователя на русском языке, машиночитаемые контракты в JSON/YAML;
  - Правовое: Полное соответствие требованиям 152-ФЗ РФ (хранение баз в РФ) и публичная оферта с отказом от ответственности за алгоритмы сторонних платформ.

## 5. СОСТАВ И СОДЕРЖАНИЕ РАБОТ ПО СОЗДАНИЮ СИСТЕМЫ
Работы выполняются по стадиям согласно ГОСТ 34.601-90:
  - Стадия 1: Формирование требований к АС (Выполнено Уровнем 0 Discovery Engine);
  - Стадия 2: Разработка концепции АС и эскизное проектирование (Выполнено 7 Министерствами);
  - Стадия 3: Техническое проектирование (Синтез схем БД и спецификаций OpenAPI 3.1);
  - Стадия 4: Рабочая документация и кодогенерация по контрактам;
  - Стадия 5: Ввод в действие и сертификация (V&V Quality Gate).

## 6. ПОРЯДОК КОНТРОЛЯ И ПРИЕМКИ СИСТЕМЫ
6.1. Виды испытаний: Предварительные автономные испытания микросервисов, приемо-сдаточные комплексные испытания и мутационное тестирование тестов.
6.2. Критерии приемки:
